## v2 features implemented (`a5219c8b36`, reworked in `11af43289e`)

- **KC_CCCV** on **Fn+C**: tap = paste (Ctrl+V), hold = copy (Ctrl+C).
  Custom keycode + timer in `process_record_user`.
- **White typing heatmap** as a custom effect (`rgb_matrix_user.inc`,
  `RGB_MATRIX_CUSTOM_USER = yes`), and the **power-on default mode**:
  every key renders the configured matrix color (default red, hue 0), and
  heat *desaturates* keys toward white at equal brightness, cooling back.
  Architecture note: QMK core only feeds keystroke heat into
  `g_rgb_frame_buffer` while the *stock* heatmap mode is active, so the keymap
  feeds it via `process_rgb_matrix_typing_heatmap()` (extern — it has no
  header) whenever the custom effect is the live mode.
- Effect cycling from the default: **Fn+Up** wraps to plain Solid Color
  (static red, no heat); **Fn+Down** returns to the heatmap.
- v2 #3 (layer indicators / numpad layer) deferred pending the search for the
  physical GMMK Numpad.

## The VIA/EEPROM lesson (important!)

With `VIA_ENABLE`, the board runs the **dynamic keymap stored in EEPROM**, not
the compiled-in one. EEPROM only re-initializes from firmware when it is reset
— so "Fn+C doesn't work" after a reflash simply meant the board was still
serving the pre-CCCV keymap. After any key change in keymap.c, flash with the
bootmagic reset: start `make ...:flash`, then unplug, **hold ESC**, replug
(bootmagic clears EEPROM and enters the bootloader in one step; verified in
`quantum/bootmagic/bootmagic.c`). RGB defaults (`RGB_MATRIX_DEFAULT_*`) also
only apply on EEPROM reset.
